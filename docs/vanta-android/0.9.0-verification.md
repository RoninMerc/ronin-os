## Implemented repairs

The previous repair loop allowed six build attempts while upload validation allowed only three. A shared six-attempt contract now fixes that mismatch. File-by-file, checkpointed generation replaces the single oversized source response for new Forge jobs; existing files are preserved unless explicitly changed. Token-limit continuation is distinct from ambiguous network interruption.

Android build access is checked before paid code generation. Build retrieval no longer requires the coding-provider key. Saved commit/run identities support nonblocking polling and prevent duplicate submissions. Actual compiler diagnostics drive targeted repairs; worker authorization/infrastructure failures are not falsely labelled model refusals. Real APKs are signed, verified and saved before completion.

Image response decoding covers actual image bytes, base64/data URIs and HTTPS delivery URLs. URLs are persisted before transfers so downloads can resume without another generation POST. Corrupt/empty results are rejected; uniformly black/white/transparent output becomes Action required, not a successful image. Featherless prompt-writing helpers require explicit approval of a real image renderer before cross-provider forwarding.

Video settings are model-specific, including required starting/reference images where supported. Restored queue inputs are validated before purchase. JSON returned with binary MIME headers is no longer misread as video. Saved delivery identity survives a transfer failure. Provider policy responses remain provider policy responses; no unrestricted-output guarantee is made.

Catalogue pagination, verified policy labels, virtualized model browsing, Prompt Architect, voice, chat, history, encrypted storage, jobs and progress are retained. Optional capability-enrichment failure no longer discards the base catalogue. Diagnostics separate worker/API/file failures and redact credentials.

## Remaining boundaries

The phone needs its own scoped private-worker GitHub token (Contents read/write, Actions read). The connected tool's account authorization cannot be transferred into the APK. Windows source can be generated, but the phone has no configured Windows compiler endpoint and does not fabricate an EXE. Generated-app runtime/unit results are not invented when the worker does not report them.

Live paid AI-account entitlement, content quality, cloud voice and real model-driven repair were not tested. The physical phone and OEM-specific background/audio behaviour were not available. Saved-state restoration after force-stop does not mean continuous execution while force-stopped. Provider restrictions still apply. No independent security audit, universal 100% reliability or commercial price valuation is claimed.
