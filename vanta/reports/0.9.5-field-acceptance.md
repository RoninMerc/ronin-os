# Vanta 0.9.5 — observed acceptance results

This record describes the executed candidate, not universal success for arbitrary generated applications.

## Candidate and implementation

Compiled source commit: `14e971edca91a13bbdfecb2e0b2ff1d422e7e129` on `fix/vanta-095-field-acceptance`.

Vanta version 0.9.5, version code 95. Standard package `com.ronin.vanta.fixed`; Personal package `com.ronin.vanta.personal`. Both delivered files retain their respective owner signing certificates verified against 0.9.4. Source and compiled payloads were compared before/after signing. No database schema or generated-app signing identity was changed.

Forge now exposes Normal plus a Low-refusal checkbox, with manual model selection optional. The low-refusal route uses eligible models with supported classifications; it is not a guarantee of model behaviour or a policy override. New source-writing requests have a checkpointed source-grounded README/install/use documentation step; existing README files are preserved. Compilation of already-written Android source no longer requires selecting or purchasing a chat model. A failed compiler with no repair model saves source/errors and requests an explicit model selection. Successful signed/exported APKs receive a source/APK hash, package, certificate, worker-run and actual test-evidence receipt.

The complete editable field-report source is bundled as an explicitly labelled working example, not as a fabricated AI response or precompiled production success. Its source, build, test, retrieval and signing paths were exercised.

## Field-report functionality and evidence

The native example captures job number, client, subject, attendance address, agent, date/time and notes. It supports typed notes, speech-recognizer result insertion, real foreground AAC/M4A memo recording, camera/system-picker photo input, PDF/Word/text/audio attachments, encrypted drafts/history and multi-page PDF output. Photo orientation is respected without rewriting original attachments.

Email handoff includes the recipient, report text, actual PDF and original attachments. An independently running test receiver with a different application UID successfully read all temporary-granted attachments. The user must review and press Send in their installed mail app. No external email was sent or falsely reported delivered. Physical speech-recognition accuracy, microphone hardware and the user's mail account were not tested.

The directly delivered demonstration APK is `com.ronin.fieldreport.demo` (Field Report Test); the editable Forge project is `com.ronin.fieldreport`. Their different identities avoid collision between the separately signed download and later device-signed Forge output. They have separate private storage.

## Explicit boundaries

The requested field-report source was authored during this task. No live OpenAI/Anthropic/Venice/Featherless keys were available for testing. Client HTTP/AI integration tests use controlled responses paired with freshly compiled exact-source artifacts; do not describe them as a live paid AI-to-worker phone run. The existing worker was separately exercised with checksum-pinned source transport. No prebuilt APK substituted for compilation.

Vanta consumes the existing private Android compiler. It does not contain an on-phone universal compiler. Windows/Tauri/macOS compilation still needs a configured matching compiler/toolchain endpoint; none was added in this Android task. No local LLMs or unrelated Ronin products were modified. The owner's physical phone remains untested. Passing these finite checks is not a promise of 100% success for every future model-generated project.
